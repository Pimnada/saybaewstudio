# การเชื่อมกล่องแชทเข้ากับ tobwai.com

ฝั่ง saybaewstudio **เสร็จแล้วและใช้งานได้** — เหลือฝั่ง tobwai ที่ต้องเปิดให้ร้านอื่นเรียกได้

---

## ฝั่งนี้ทำอะไรไปแล้ว

| ไฟล์ | หน้าที่ |
|---|---|
| `inc/chat-widget.php` | ปุ่มลอย + กล่องแชท แสดงเมื่อเปิดสวิตช์และกรอกรหัสร้านแล้วเท่านั้น |
| `public/assets/js/chat.js` | ยิง `fetch` ไปที่ tobwai พร้อม `vid` ประจำเบราว์เซอร์ |
| `public/admin-chat.php` | สวิตช์เปิด/ปิด · รหัสร้าน · ที่อยู่ API · ข้อความทักทาย · ปุ่มทดสอบการเชื่อมต่อ |

**ถ้ายังไม่ได้กรอกรหัสร้าน กล่องแชทจะไม่แสดงเลย** ตั้งใจให้เป็นแบบนั้น — ไม่มีกล่อง
ดีกว่ามีกล่องที่ลูกค้ากดแล้วขึ้น error

ข้อมูลบทสนทนา **ไม่ได้เก็บที่เว็บนี้เลย** ทั้งหมดอยู่ที่ tobwai ซึ่งเป็นที่เดียวกับ
ที่รับข้อความจาก LINE และ Facebook อยู่แล้ว ทีมงานจึงเปิดที่เดียว

## สิ่งที่ widget ส่งไป

```
POST <chat_endpoint>
Content-Type: application/json

{
  "action": "send",
  "vid":    "0f3a...c1",     // hex 32 ตัว ต่อหนึ่งเบราว์เซอร์ เก็บใน localStorage
  "text":   "ข้อความจากลูกค้า",
  "key":    "<รหัสร้านของสตูดิโอ>"
}
```

สิ่งที่คาดหวังกลับมา

```json
{ "ok": true, "reply": "ข้อความตอบกลับ" }
```

หรือเมื่อผิดพลาด

```json
{ "ok": false, "error": "rate_limited" }
```

`chat.js` แปล `error` เป็นภาษาที่ลูกค้าเข้าใจ และทุกกรณีที่ล้มเหลวจะบอกให้ไปทาง LINE แทน
ไม่ปล่อยให้เงียบ

## สิ่งที่ฝั่ง tobwai ต้องทำเพิ่ม

`chat-api.php` ตอนนี้ล็อกไว้ที่ร้านเดียว

```php
const TOBWAI_CHAT_SITE_ID = 1;   // ร้าน Tobwai.com เอง
```

และคอมเมนต์ในไฟล์เขียนไว้เองว่า *"ไม่ใช่ multi-tenant เหมือน webhook LINE/Facebook ของลูกค้าร้านอื่น"*
จึงยังรับ `key` จากร้านอื่นไม่ได้ ต้องแก้ 4 อย่าง

### 1. เก็บรหัสร้านต่อ site
เพิ่มคอลัมน์ใน `sites` แบบ guarded ALTER (db.php ของ tobwai ทำ migration เองอยู่แล้ว)

```
web_chat_key     VARCHAR(64)   -- สุ่มตอนเปิดใช้งาน
web_chat_origin  VARCHAR(190)  -- โดเมนที่อนุญาต เช่น https://saybaewstudio.com
```

### 2. เลือก site จาก key แทนค่าคงที่
เปลี่ยน `TOBWAI_CHAT_SITE_ID` จากค่าคงที่เป็นตัวแปรที่ resolve ต่อ request

- ไม่มี `key` → ใช้ site 1 เหมือนเดิมทุกประการ **พฤติกรรมเดิมต้องไม่เปลี่ยน**
- มี `key` → หา site จาก `web_chat_key` ถ้าไม่เจอตอบ `{"ok":false,"error":"bad_key"}`

ค่าคงที่นี้ถูกใช้ประมาณ 6 จุดในไฟล์ ต้องเปลี่ยนให้ครบทุกจุด
(`tobwai_inbox_record`, การนับข้อความแรก, การเช็ก entitlement, แคช ฯลฯ)

### 3. CORS
เป็นการเรียกข้ามโดเมน ต้องตอบ preflight และส่ง header กลับ

```php
if (($_SERVER['REQUEST_METHOD'] ?? '') === 'OPTIONS') { /* ตอบ 204 พร้อม header ด้านล่าง */ }
header('Access-Control-Allow-Origin: ' . $site['web_chat_origin']);
header('Access-Control-Allow-Headers: Content-Type');
header('Vary: Origin');
```

**ห้ามใช้ `*`** — ต้องเทียบกับ `web_chat_origin` ของร้านนั้นเท่านั้น ไม่งั้นเว็บใดก็ได้
ยิง API ด้วยรหัสที่หลุดออกไปแล้วกินโควตา AI ของลูกค้าได้

### 4. หน้าให้ลูกค้าดูรหัสของตัวเอง
ในหลังบ้าน tobwai ต้องมีที่ให้ร้านกดสร้าง/ดู `web_chat_key` และกรอกโดเมนของตัวเอง

## ทำไมยังไม่ลงมือแก้ฝั่ง tobwai

tobwai คือระบบที่ลูกค้าจ่ายเงินใช้อยู่จริง การเปลี่ยน `chat-api.php` กระทบ
กล่องแชทบนหน้า tobwai.com เองด้วย ควรมีคนตรวจ diff ก่อนปล่อยขึ้น ไม่ใช่ปล่อยเงียบ ๆ
ระหว่างที่ไม่มีใครดูอยู่

เมื่อฝั่ง tobwai พร้อม เอา `web_chat_key` มากรอกที่ **หลังบ้าน → ระบบแชท** แล้วกด
**ทดสอบการเชื่อมต่อ** ปุ่มนั้นยิง request จริงด้วยรูปแบบเดียวกับที่เบราว์เซอร์ใช้
และรายงานผลตรง ๆ ว่าได้อะไรกลับมา
